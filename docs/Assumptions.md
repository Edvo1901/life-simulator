# Technical decisions

- Use installed Node 24.19.0/pnpm 12.6.0 without wrappers, .tools, or a bootstrap script folder. Keep exact existing framework/package pins and per-app lockfiles.
- wiki is a regular main-repository folder by owner instruction, replacing the earlier submodule standard. Its requested authentication/localization/API pages are authorized. No Git repository, commit, push, or online publication is created by this work.
- English is the initial default/fallback; root language/en and language/vn contain shared namespaces. language/languages.json is the fixed supported-language exception to database-driven business options. vn maps to HTML vi. New folders/namespaces are discovered by the server resource loader. Keep route URLs unchanged; persist only language preference under life-simulator.language. Client/server initial rendering is English before restoring preference. Root resources require the project folder at runtime; installer packaging remains future scope.
- Shared i18next provider/setup lives in existing layout/lib folders; there is no additional provider/state framework. Next uses the project root consistently for Turbopack/file tracing to include root language resources; the server loader passes resources/registry to the provider without direct client imports from outside frontend. IBM Plex Sans includes Vietnamese glyphs; en-AU/AUD formatting and Adelaide storage remain unchanged.
- Username length is 1–50 without edge whitespace/control characters. Preserve case and enforce exact SQL uniqueness using BIN2. Deleted names remain reserved. Password minimum is eight Unicode characters with 72 UTF-8-byte maximum (bcrypt boundary), cost 12. Public registration always assigns user.
- Sessions use random 32-byte opaque bearer tokens, hashed keys in backend memory, eight-hour expiry, and current-account/security-stamp validation. Browser tokens are memory-only. Logout revokes the token; changes to password/role/status and deletion rotate stamps, invalidating prior sessions. Backend restart or app/page reload requires login again. Language preference has no auth data.
- First-admin setup is explicit backend setup:admin with local env credentials; no public bootstrap endpoint or seeded password. Serialize bootstrap/admin writes and preserve the final enabled undeleted administrator. No account username editing, email recovery, MFA, or custom role editor was requested.
- Five-digit USR IDs cover the owner-confirmed 10,000 lifetime capacity; schema_v1.sql is owner-named. Roles use natural role_code keys, not generated user IDs. SQL writes stay in repositories and service transaction boundaries use the opaque AuthTransactionRunner. Only isolated test databases may be created/dropped automatically by tests; configured database execution awaits explicit approval.
- Root Prettier serves all apps. Global exception filtering returns safe stable codes without sensitive exception text. Auth registration/login is limited to 20 attempts/minute per IP/endpoint on loopback; JSON bodies default to 16 KiB. Backend CORS remains an explicit allowlist. Electron binds loopback, rejects occupied ports, and stops only owned trees.
- Frontend startup preserves the native .env.local loader; backend loads .env then .env.local with shell precedence. Electron injects actual public API URL/prefix while stripping DB_/AUTH_ shell settings from frontend child env. Missing public API settings were appended to frontend/.env.local to match its configured backend; no backend credential was changed.
- Native translation requires only desktopLanguage.setLanguage through a sandboxed preload. Main-process validation checks registered code, sender ID, main frame, and frontend origin. No native filesystem/process/SQL/token capability is exposed. Native labels/resources are local; OS-provided UI follows OS language.
- Production Next builds still download IBM Plex Sans and Electron setup downloads its binary. Runtime translations require no online service. No game simulation, image upload, installer, updater, or hosting is implemented.
